[X] Si tengo ofertas aceptadas pendientes de pago ese tab no carga y la consola muestra un error ERR_INCOMPLETE_CHUNKED_ENCODING . Esto es un error grave.
  -- RESUELTO: mismo bug que el anterior

[X] Hacen el control de acceso por ownership a mano, con if + throw en los controllers y, para las acciones de escritura, solo en los services, sin ninguna regla de Spring Security (@PreAuthorize O .access(...) ) para esos recursos. Por ejemplo, AccountController.incomingOfferDetail Y OfferServiceImpl.accept. Esto es un error conceptual grave.
  -- RESUELTO: PR https://bitbucket.org/itba/paw-2026b-08/pull-requests/83

[X] En el registro, el controller llama a dos services distintos que escriben, cada uno en su propia transacción: UserController.register crea el usuario y después genera el código de verificación. Si la segunda operación falla, la primera ya quedó confirmada. Esto es un error conceptual grave.
  -- RESUELTO: PR https://bitbucket.org/itba/paw-2026b-08/pull-requests/82

[ ] Tienen lógica de negocio en los controllers, por ejemplo (pero no únicamente): deciden el monto y el tipo de la oferta, qué estados cuentan como vendido, si una oferta ya fue calificada o si un admin puede suspenderse en CheckoutController.checkoutPost Y ListingController.listing. Esto es un error conceptual grave.

[ ] Verifican el resultado de una escritura con otro método del mismo DAO en lugar de consultar la tabla. Por ejemplo, OfferJdbcDaoTest.testUpdateProof0fPaymentId usa offerDao.getById. Esto es un error conceptual grave.
